# Static Pods

- A ```Static Pod``` is managed directly by the kubelet on a specific node, not by the kube-scheduler. The kubelet watches a manifest directory, commonly: ```/etc/kubernetes/manifests```

- When a YAML file is added there, kubelet creates the Pod on that node. If the file is removed, kubelet deletes the Pod.

- Static Pods usually appear in kubectl get pods as mirror Pods, but they cannot be directly managed through the API server.


## Static Pod Operations - KinD Cluster

### Creating a Static Pod inside a Kind Cluster

```bash
docker exec -it cka-cluster-control-plane bash

vim /etc/kubernetes/manifests/static-nginx.yaml

apiVersion: v1
kind: Pod
metadata:
  name: static-nginx
spec:
  containers:
    - name: nginx
      image: nginx
      ports:
        - containerPort: 80

kubectl get pods -o wide
```

**The Pod name will usually include the Node name:**

```bash
<pod-name>-<node-name>
static-nginx-cka-cluster-control-plane
```

### Delete the Static Pod

Delete it by removing the manifest:

```bash
docker exec cka-cluster-control-plane rm /etc/kubernetes/manifests/static-nginx.yaml
```

### Concept on kube-scheduler

The ```kube-scheduler``` usually runs as a static Pod from /etc/kubernetes/manifests. If its manifest is removed, new Pods remain Pending until the manifest is restored.
