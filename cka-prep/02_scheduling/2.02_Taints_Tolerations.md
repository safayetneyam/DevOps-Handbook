# Taints & Tolerations

## Taint
### Basic concept

**Taints are applied to Nodes, while tolerations are applied to Pods.**

- A taint repels Pods from a Node.
- A toleration permits a Pod to be scheduled on a Node with a matching taint.
- A toleration does not force the Pod to run on that Node; the scheduler still evaluates resources, affinity rules, selectors, and other constraints.

### Taint Structure

```yaml
key=value:effect
workload=database:NoSchedule

maintenance:NoSchedule      # value is optional
```

| Part   | Value        | Meaning                                  |
| ------ | ------------ | ---------------------------------------- |
| Key    | `workload`   | Name of the restriction                  |
| Value  | `database`   | Category or value                        |
| Effect | `NoSchedule` | Action taken against non-tolerating Pods |

### Taint Effects

| Effect             | New Pods                                | Existing Pods                   |
| ------------------ | --------------------------------------- | ------------------------------- |
| `NoSchedule`       | Non-tolerating Pods cannot be scheduled | Remain running                  |
| `PreferNoSchedule` | Scheduler tries to avoid the Node       | Remain running                  |
| `NoExecute`        | Non-tolerating Pods cannot be scheduled | Non-tolerating Pods are evicted |

### Imposing Taint

```bash
kubectl taint nodes <name-of-node> <key>=<value>:<effect>

kubectl taint node worker1 workload=database:NoSchedule
kubectl taint node worker1 workload=database:PreferNoSchedule
kubectl taint node worker1 maintenance=true:NoExecute

# overwrite an existing taint
kubectl taint nodes worker1 workload=frontend:NoSchedule --overwrite
```

```yaml
# declarative approach
apiVersion: v1
kind: Node
metadata:
  name: worker1
spec:
  taints:
    - key: workload
      value: database
      effect: NoSchedule
```

Check `Taint` on a Node

```bash
kubectl describe node worker1

# look for
Taints: workload=database:NoSchedule
```

### Removing Taint

```bash
# add a - (dash or minus) sign at the end
kubectl taint nodes <name-of-node> <key>=<value>:<effect>-
kubectl taint nodes worker1 workload=database:NoSchedule-

kubectl taint nodes worker1 workload-   # remove all train with a particular key
```

## Toleration

### Toleration - Declarative Command 

Suppose the Node contains this taint: `workload=database:NoSchedule`

The matching Pod toleration is:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: database-pod
spec:
  tolerations:
    - key: workload
      operator: Equal
      value: database
      effect: NoSchedule

  containers:
    - name: database
      image: nginx:1.27
```

### Toleration Operators

| Operator | Value required? | Meaning                                              |
| -------- | --------------: | ---------------------------------------------------- |
| `Equal`  |             Yes | Key and value must match                             |
| `Exists` |              No | Any value with the specified key                     |
| `Gt`     |             Yes | Numeric taint value greater than the specified value |
| `Lt`     |             Yes | Numeric taint value less than the specified value    |

<br>

`Equal`: Requires the key, value, and effect to match. *Default*.

```yaml
tolerations:
  - key: workload
    operator: Equal
    value: database
    effect: NoSchedule
```
- Matches: `workload=database:NoSchedule`

<br>

`Exists`: Checks whether the taint key exists. The value must be omitted.

```yaml
tolerations:
  - key: workload
    operator: Exists
    effect: NoSchedule
```
- Matches: 
    ```
    workload=database:NoSchedule
    workload=frontend:NoSchedule
    workload=backend:NoSchedule
    ```

**When effect is omitted, the toleration matches all effects for the specified key. When both value and effect are omitted, the toleration matches all values and effects for the specified key**:

```yaml
tolerations:
  - key: workload
    operator: Exists
```
- Matches: 
    ```
    workload=frontend:NoSchedule
    workload=frontend:PreferNoSchedule
    workload=frontend:NoExecute

    workload=database:NoSchedule
    workload=database:PreferNoSchedule
    workload=database:NoExecute
    ```

**An empty key with Exists matches all taint keys and values**:
```yaml
tolerations:
  - operator: Exists
```
- This effectively tolerates every taint and should be used cautiously.

<br>

`Gt` or `Lt`: Performs a numeric comparison.
```yaml
tolerations:
  - key: reliability
    operator: Gt
    value: "95"
    effect: NoSchedule
```
- Matches: 
    ```bash
    taint value > toleration value

    reliability=99:NoSchedule   # matched
    reliability=90:NoSchedule   # not matched
    ``` 

---

**Points to be noted**:

```yaml
Equal = exact key-value match
Exists = match any value for that key
```
