# Job

- A Job creates one or more Pods to perform a task and tracks its successful completion.
- After the task finishes, the Pods are marked Completed; deleting the Job also removes its Pods.

### Job - Imperative Commands

```yaml
kubectl create job <job-name> --image=<image> -- <command> <arguments>

kubectl create job hello-job --image=busybox:1.36 -- /bin/sh -c 'echo "Job completed successfully"'
```
- ```-c``` tells ```/bin/sh``` to execute the next argument as a *command string*.

### Job - Declarative Commands

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: hello-job
spec:
  backoffLimit: 3
  template:
    spec:
      restartPolicy: Never
      containers:
        - name: hello
          image: busybox:1.36
          command:
            - /bin/sh
            - -c
            - echo "Job completed successfully"
```

- ```backoffLimit``` defines how many times Kubernetes retries a failed Job before marking it as Failed.
- ```restartPolicy``` defines whether Kubernetes restarts a container after it stops or fails. 
  - Types are: ```Always```, ```OnFailure```, ```Never```

### Job - Operations

```yaml
kubectl get jobs
kubectl get pods
kubectl describe job hello-job
kubectl logs job/hello-job      # gives the terminal output

kubectl delete job <name-of-job>
kubectl delete hello-job
```

### Job - Automatic YAML Template Generation

```yaml
kubectl create job hello-job --image=busybox:1.36 --dry-run=client -o yaml -- bin/sh -c 'echo "Job completed successfully"'
```

# CronJob

A **CronJob** creates Jobs automatically on a repeating schedule. It is useful for regular tasks such as backups, report generation, cleanup, and data processing. Each scheduled Job creates a Pod to perform the task.

**Why use a CronJob?**
- Automates recurring tasks using a cron schedule.
- Tracks each execution as a Kubernetes Job and can retry failed tasks.

**Cron Format**

```bash
┌─ minute
│ ┌─ hour
│ │ ┌─ day of month
│ │ │ ┌─ month
│ │ │ │ ┌─ day of week
│ │ │ │ │
* * * * *
```

### CronJob - Imperative Command

```bash
kubectl create cronjob <name> --image=<image> --schedule="<cron-expression>" -- <command>

kubectl create cronjob backup-cronjob --image=busybox:1.36 --schedule="*/5 * * * *" -- /bin/sh -c 'date; echo "Backup completed"'
```

### CronJob - Declarative Command

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup-cronjob
spec:
  schedule: "*/5 * * * *"
  successfulJobsHistoryLimit: 10  # Default 3 (Optional)
  failedJobsHistoryLimit: 3       # Default 1 (Optional)
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: backup
              image: busybox:1.36
              command:
                - /bin/sh
                - -c
                - 'date; echo "Backup completed"'
```

- ```successfulJobsHistoryLimit: 10```: Keeps the latest 10 successfully completed Jobs.
- ```failedJobsHistoryLimit: 3```: Keeps the latest 3 failed Jobs.

### CronJob - YAML Template Generation

```bash
kubectl create cronjob backup-cronjob --image=busybox:1.36 --schedule="*/5 * * * *" --dry-run=client -o yaml -- /bin/sh -c 'date; echo "Backup completed"'
```

### CronJob - Operations

```yaml
kubectl get cronjobs
kubectl get jobs
kubectl get pods

kubectl delete cronjob <name-of-cronjob>
kubectl delete cronjob backup-cronjob
```
