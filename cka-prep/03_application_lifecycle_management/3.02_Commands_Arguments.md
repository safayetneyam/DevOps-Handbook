# Configuring Commands & Arguments on Application

- Commands and arguments determine which process runs inside a container and what parameters are passed to it.

- **Dockerfile vs Kubernetes Pod**

    | Dockerfile | Kubernetes Pod | Purpose |
    | --- | --- | --- |
    | `ENTRYPOINT` | `command` | Main executable/process |
    | `CMD` | `args` | Default arguments passed to the executable |

## `Dockerfile` Instructions

- `ENTRYPOINT`: Defines the main executable: `ENTRYPOINT ["python", "app.py"]`
- `CMD`: Provides default arguments: `CMD ["--port", "8080"]`
- The final command becomes: `python app.py --port 8080`

### Complete Dockerfile

```Dockerfile
FROM python:3.12

WORKDIR /app
COPY app.py .

ENTRYPOINT ["python", "app.py"]
CMD ["--port", "8080"]
```

## Kubernetes Instructions

### Complete Pod Configuration

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: python-app
spec:
  containers:
    - name: app
      image: my-python-app:v1
      command:
        - python
        - app.py
      args:
        - --port
        - "8080"
```
- The executed command is: `python app.py --port 8080`

## Override Behaviour

```Dockerfile
ENTRYPOINT ["python", "app.py"]
CMD ["--port", "8080"]
```

- **No Override**

    ```yaml
    containers:
    - name: app
        image: my-python-app:v1
    ```
    Runs: `python app.py --port 8080`

- **Override only Agruments**

    ```yaml
    containers:
    - name: app
        image: my-python-app:v1
        args:
        - --port
        - "9090"
    ```
    Runs: `python app.py --port 9090`

- **Override Command and Arguments**

    ```yaml
    containers:
    - name: app
        image: my-python-app:v1
        command:
        - python
        - test.py
        args:
        - --debug
    ```
    Runs: `python test.py --debug`

    Both Docker `ENTRYPOINT` and `CMD` are replaced.

## Shell Command Example

- Kubernetes does not automatically start a shell. Use `sh -c` when using variables, pipes, redirection, or multiple commands.

    ```yaml
    apiVersion: v1
    kind: Pod
    metadata:
    name: command-demo
    spec:
    containers:
        - name: busybox
        image: busybox
        command:
            - sh
            - -c
        args:
            - |
            echo "Starting application"
            echo "Hostname: $HOSTNAME"
            sleep 3600
    ```

    Without `sh -c`, shell features such as `$HOSTNAME`, `&&`, `|`, and `>` may not work.
