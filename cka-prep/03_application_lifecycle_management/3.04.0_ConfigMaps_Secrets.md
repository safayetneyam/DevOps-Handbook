# ConfigMaps

- A **ConfigMap** stores non-sensitive configuration as key-value pairs, separating configuration from Pod YAML and container images. It can be consumed as environment variables, command arguments, or mounted files. ConfigMaps do not provide secrecy or encryption.

## ConfigMap - Imperative Command

```yaml
kubectl create configmap app-cm --from-literal=firstname=Safayet --from-literal=lastname=Neyam

# or
kubectl create configmap app-cm --from-file=app.properties
```

## ConfigMap -  Declarative Command

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  firstname: "Safayet"
  lastname: "Neyam"
  APP_NAME: "shopping-app"
  APP_ENV: "production"
  APP_PORT: "8080"
```

## Use One ConfigMap Key

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
spec:
  containers:
    - name: myapp
      image: busybox:1.28
      command: ["sh", "-c", "echo $FIRSTNAME && sleep 3600"]
      env:
        - name: FIRSTNAME
          valueFrom:
            configMapKeyRef:
              name: app-config
              key: firstname
```

## Use All ConfigMap Keys
`envFrom` converts every ConfigMap key into an environment variable.

```yaml
envFrom:
  - configMapRef:
      name: app-config
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-pod
spec:
  containers:
    - name: app
      image: busybox
      command:
        - sh
        - -c
        - |
          echo "Name: $APP_NAME"
          echo "Environment: $APP_ENV"
          echo "Port: $APP_PORT"
          sleep 3600
      envFrom:
        - configMapRef:
            name: app-config
```


## Checking the Values

```yaml
kubectl logs app-pod

# ===== Output ======
# Name: shopping-app
# Environment: production
# Port: 8080
```

# Secrets

- A **Secret** stores sensitive information such as passwords, tokens, certificates, and SSH keys separately from Pod definitions. Pods can consume Secrets as environment variables or mounted files.

## Common Secret Types

| Type | Purpose |
| --- | --- |
| `Opaque` | General user-defined sensitive data |
| `kubernetes.io/dockerconfigjson` | Private registry credentials |
| `kubernetes.io/basic-auth` | Username and password |
| `kubernetes.io/ssh-auth` | SSH private key |
| `kubernetes.io/tls` | TLS certificate and key |
| `bootstrap.kubernetes.io/token` | Cluster bootstrap token |

- `Opaque` is the default type when no specific type is provided.


## Secrets -  Imperative Command

```bash
kubectl create secret generic demo-secret --from-literal=username=admin --from-literal=password=my-password
```

## Secrets -  Declarative Command

- Using `stringData` allows plain-text input.
    
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: database-secret
type: Opaque
stringData:
  username: admin
  password: my-secure-password
```

- Using `data` requires Base64-encoded values. 
- Base64 is encoding, not encryption. Kubernetes Secrets are stored unencrypted by default unless encryption at rest is configured. 
- Kubernetes automatically decodes Secret values when exposing them as environment variables or mounted files.
    
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: demo-secret
type: Opaque
data:
  username: YWRtaW4=
  password: bXktcGFzc3dvcmQ=
```

## Use One Secret Key

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: database-client
spec:
  containers:
    - name: client
      image: busybox:1.36
      env:
        - name: DB_USERNAME
          valueFrom:
            secretKeyRef:
              name: database-secret
              key: username
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: database-secret
              key: password
      command: ["sh", "-c"]
      args:
        - |
          echo "Connecting as $DB_USERNAME"
          test -n "$DB_PASSWORD" && echo "Password loaded successfully"
          sleep 3600
```
- The application accesses the Secret through the `$DB_USERNAME` and `$DB_PASSWORD` environment variables. 
- Avoid printing the actual password in production. `test -n "$DB_PASSWORD"`

```bash
kubectl apply -f secret-pod.yaml
kubectl logs database-client

# ==== Output ====
# Connecting as admin
# Password loaded successfully
```

## Use All Secrets

```yaml
envFrom:
  - secretRef:
      name: demo-secret
```

## Useful Commands

```bash
kubectl get configmaps
kubectl describe configmap app-cm

kubectl get secrets
kubectl describe secret demo-secret
```

## Decode Base65 Secret Value

```bash
kubectl get secret demo-secret -o jsonpath='{.data.password}' | base64 --decode
```

### As a Mounted File

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
data:
  password: bXlwYXNzd29yZA==   # Base64 of "mypassword"

---

spec:
  containers:
    - name: app
      image: busybox
      command: ["sh", "-c", "cat /etc/secret/password; sleep 3600"]
      volumeMounts:
        - name: secret-volume
          mountPath: /etc/secret
          readOnly: true

  volumes:
    - name: secret-volume
      secret:
        secretName: app-secret
```

### Docker Registry Secret 

```bash
# Imperative
kubectl create secret docker-registry registry-secret --docker-server=registry.example.com --docker-username=neyam10cb --docker-password=neyam10cb --docker-email=neyam10cb@example.com

# Declarative
--dry-run=client -o yaml
```

```yaml
spec:
  imagePullSecrets:
    - name: registry-secret

  containers:
    - name: app
      image: registry.example.com/my-app:v1
```

### Basic Authentication Secret

```yaml
# Imperative
kubectl create secret generic basic-auth-secret --type=kubernetes.io/basic-auth --from-literal=username=admin --from-literal=password='my-password'

# Declarative
apiVersion: v1
kind: Secret
metadata:
  name: basic-auth-secret
type: kubernetes.io/basic-auth
stringData:
  username: admin
  password: my-password
```

### SSH Authentication Secret

```yaml
# Imperative
kubectl create secret generic ssh-secret --type=kubernetes.io/ssh-auth --from-file=ssh-privatekey=$HOME/.ssh/id_rsa

# Declarative
apiVersion: v1
kind: Secret
metadata:
  name: ssh-secret
type: kubernetes.io/ssh-auth
stringData:
  ssh-privatekey: |
    -----BEGIN OPENSSH PRIVATE KEY-----
    PASTE_PRIVATE_KEY_HERE
    -----END OPENSSH PRIVATE KEY-----
```

### TLS Secret

```yaml
# Imperative
kubectl create secret tls tls-secret --cert=./tls.crt --key=./tls.key

# Declarative
apiVersion: v1
kind: Secret
metadata:
  name: tls-secret
type: kubernetes.io/tls
stringData:
  tls.crt: |
    -----BEGIN CERTIFICATE-----
    PASTE_CERTIFICATE_HERE
    -----END CERTIFICATE-----
  tls.key: |
    -----BEGIN PRIVATE KEY-----
    PASTE_PRIVATE_KEY_HERE
    -----END PRIVATE KEY-----
```

```text
current-directory/
├── tls.crt
└── tls.key
```

### Bootstrap Token Secret

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: bootstrap-token-abcdef
  namespace: kube-system
type: bootstrap.kubernetes.io/token
stringData:
  description: "Token for joining worker nodes"
  token-id: abcdef
  token-secret: 0123456789abcdef
  usage-bootstrap-authentication: "true"
  usage-bootstrap-signing: "true"
  auth-extra-groups: system:bootstrappers:kubeadm:default-node-token
```

- Used primarily when a new Node joins a cluster.
- The name must follow `bootstrap-token-<token-id>`, and the Secret must be in the `kube-system` namespace.
